# SSQP examples
This directory contains all existing examples for the SSQP library. These examples include robotics-related OCPs for trajectory generation, as well as MPC on simulators and real systems.

Specifically:

* [`trajgen`](trajgen) is the directory containing trajectory generation examples, in both Python and C++. These examples use SSQP to fully generate trajectories offline from scratch, often by providing relevant costs and constraints, as well as next to no additional initialization. They cover pendulums, the Panda and iiwa arms, the A1 and Go2 quadrupeds, and the G1 and Talos humanoids, and write their results to JSON files. Many of the Python ones take command line parameters.
* [`mujoco_mpc`](mujoco_mpc) is the directory containing MPC examples for simulations. These simulations use [MuJoCo](https://mujoco.org/) as the simulator and SSQP as the controller. The simulator acts as the real system, providing feedback regarding the current state, while SSQP uses that feedback to generate and solve OCPs that determine the system controls for the next step. The simulation is synced with the controller, so it does not run in real time. Examples cover the pendubot, the Panda and the Go2.
* [`real_mpc`](real_mpc) is the directory containing MPC examples for real systems. This works similarly to `mujoco_mpc`, but here, instead of a simulator, we use a real world system (i.e. a robot) to get state information and apply our generated controls. Examples cover double pendulums, a Franka Emika Panda and a Unitree Go2, and have been tested on real hardware.
* [`visualizer`](visualizer) is the directory containing the visualization scripts. `visualize.py` uses [viser](https://viser.studio/main/) to visualize trajectories generated by our solver (and written to an output JSON file using the provided `solver.write` method) in the browser, and `visualize_srbd.py` does the same for single rigid body trajectories in a matplotlib window.
* [`models`](models) includes custom SSQP models that may be used in place of XML files, as well as utilities related to those models. These are the single rigid body model of a quadruped (`quadruped_srbd`) and the high-level planner (`quadruped_hlplanner`), which generates the contact schedules, footholds and base references for the quadruped walking examples.
* [`assets`](assets) includes assets such as URDF and MJCF files. The URDFs used by SSQP's built in model presets (Go2, A1, Panda, G1, Talos and the double pendulum) come from here, and are embedded into the library when it is built.

The benchmarks, which compare various aspects of our solver, such as the performance of the forward and inverse dynamics formulations for OCPs, live in the `benchmarks` directory at the root of the repository.

### Running the Python examples
Note that, to execute the Python examples, the generated Python library for SSQP must be available to Python upon execution.

Once the Python extension has been built, source the `setup_env.sh` script, located in this directory:

```
source setup_env.sh
```

You can now execute any of the examples from their directory via:

```
python example.py
```

Each directory has its own README, with more details about its examples, including the parameters they take and any additional requirements.
