# Trajectory visualizers

These scripts play back trajectories generated by SSQP and written to a JSON file with the solver's `write` method, such as the ones produced by the [`trajgen`](../trajgen) examples. There are two of them:

- `visualize.py` is the main visualizer. It animates any robot from its URDF in a 3D viewer in the browser, using [viser](https://viser.studio/main/).
- `visualize_srbd.py` animates trajectories of the single rigid body model of a quadruped (such as the `go2_srbd_walk.py` and `go2_srbd_jump.py` examples), in a matplotlib window.

## Running the visualizers

Make sure the environment is set up as described in the [examples README](../README.md), with `viser` (and its `yourdfpy` and `trimesh` dependencies) installed for `visualize.py`, and `matplotlib` for `visualize_srbd.py`. The repository's `.gitignore` lists `viser-venv`, the virtual environment name we use for this.

Run them from this directory, for example:

```
python visualize.py -u ../assets/urdf/go2/go2.urdf -i ../trajgen/data/go2_jump.json
```

## `visualize.py`

The script starts a viser server on port 8080, so after launching it, open `http://localhost:8080` in a browser to see the robot. Orbit, pan and zoom with the mouse. It plays the trajectory back at the time step the solver used, so the motion plays at real time, and the speed can be scaled with `--delay-factor`.

The trajectory file must be the JSON written by `solver.write`, and the URDF given must be the one of the model that generated it, since the state in the file is mapped onto the URDF's joints. Models with floating bases (the quadrupeds and humanoids) and fixed bases (arms and pendulums) are both supported. If the trajectory has contact forces, they can be drawn as arrows at the feet.

If the file contains a terrain (a slope, stairs, or a heightmap, as set on the model), it is drawn around the robot's trajectory. Without one, the ground is drawn as a flat plane.

| Parameter | Description |
|---|---|
| `-u`, `--urdf-path` | Path to the URDF of the robot (required) |
| `-i`, `--input` | Path to the trajectory JSON file (required) |
| `-d`, `--delay-factor` | Factor to delay each time step by, to slow down (above 1) or speed up (below 1) playback (default 1.0) |
| `-l`, `--loop` | Loop the trajectory after it ends |
| `-g`, `--no-ground` | Do not draw the ground |
| `-f`, `--forces` | Draw the contact forces |
| `--goal X Y Z` | Draw a goal point |
| `--circle CX CY CZ R` | Draw a circle on the yz-plane, for example the path of a circle tracking example |
| `--box-region XMIN YMIN ZMIN XMAX YMAX ZMAX` | Draw a box, for example a constraint region |
| `--shaded-model-base X Y Z QW QX QY QZ` | Position and orientation of an additional, semi-transparent copy of the robot, which can be used to show a start or a target pose (default: the origin, with no rotation) |
| `--shaded-model-configuration Q ...` | Configuration of that shaded copy (default: the robot's first configuration in the trajectory) |

## `visualize_srbd.py`

Plays back a trajectory of the single rigid body model in a matplotlib 3D plot: the center of mass and its trail, the body as a rectangle oriented by the base's rotation, and each foot with its trail. The animation repeats until the window is closed. It needs no URDF, since the trajectory contains the foot positions directly.

| Parameter | Description |
|---|---|
| `-i`, `--input` | Path to the trajectory JSON file (required) |
| `--body-length` | Length of the body rectangle (default 0.4) |
| `--body-width` | Width of the body rectangle (default 0.2) |
| `--view-radius` | Half-extent of the view around the center of mass (default 0.6) |
| `--fixed-limits` | Fix the axis limits instead of following the robot |
| `-f`, `--forces` | Draw the foot contact forces as arrows |
| `--force-scale` | Scale applied to the force arrows (default 0.003) |
