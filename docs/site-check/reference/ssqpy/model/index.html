ssqpy.model¶

model ¶

Submodule containing classes related to the SSQP model, a respresentation of the
system used for optimization.

SolverMode ¶

Bases: Enum

Solver Mode
The mode the solver uses for the system formulation, corresponding to the
equality constraint of the NLP
This can either be full dynamics, or a kinematics formulation
Options:

  • Kinematics: The solver optimizes in a kinematic mode. This means there are no system dynamics. Instead, the generated controls correspond to velocities, while the state corresponds to the system configuration.
  • ForwardDynamics: The solver optimizes with a forward dynamics approach. The state corresponds to a stacked vector of the system configuration and velocity. The generated controls correspond to torques which, when applied over time to the system, generate the output trajectory.
  • InverseDynamics: The solver optimizes with an inverse dynamics approach. The state corresponds to a stacked vector of the system configuration and velocity. The generated controls correspond to accelerations. This simplifies the LQR formulation and can sometimes lead to more robust solutions. Inverse dynamics is used as a constraint, ensuring the torques producing the generated acceleration controls are within the required effort limits.
  • ReducedInverseDynamics: This mode is similar to the Inverse dynamics mode. In this mode, the floating base (if present) and/or some subset of the model's joints are unactuated. While regular Inverse mode enforces this via equality constraints, this mode instead enforces this implicitly through state propagation.

Integration ¶

Bases: Enum

The type of integration used for the system dynamics
Options:

  • ExplicitEuler: \(\boldsymbol{x}_{n+1}=\boldsymbol{x}_n+\boldsymbol{v}_ndt\) \(\boldsymbol{v}_{n+1}=\boldsymbol{v}_n+\boldsymbol{a}_ndt\)
  • SemiImplicitEuler: \(\boldsymbol{x}_{n+1}=\boldsymbol{x}_n+\boldsymbol{v}_{n+1}dt\) \(\boldsymbol{v}_{n+1}=\boldsymbol{v}_n+\boldsymbol{a}_ndt\)

ReferenceFrame ¶

Reference frame of a predefined cost or constraint
Selects the axes that a cost's error, weights and desired value, or a
constraint's bounds, are expressed along. Only the axes change:
positions keep the world origin, unless a bound's center moves it
Options:

  • ReferenceFrame.World: The world axes
  • ReferenceFrame.Local: The axes of the frame the cost or constraint acts on, moving with it
  • ReferenceFrame(rotation): Fixed axes given by a rotation matrix \(R\), whose columns are the axes in world coordinates. A vector \(\boldsymbol{v}\) in world coordinates is then expressed as \(R^\top \boldsymbol{v}\). A 3x3 array converts to these implicitly
  • ReferenceFrame.yaw(angle), ReferenceFrame.normal(normal, yaw): Fixed axes built from a yaw angle, or from a surface normal and a yaw angle
  • ReferenceFrame.Base: The axes of the model's floating base, moving with it. On floating base costs and constraints, this is the same as Local Each cost or constraint documents the options it supports, and raises ValueError when given another

Model ¶

Model(horizon, dt, **kwargs)

Defines an SSQP model
An SSQP model object is a prerequisite to performing optimization using SSQP
The model contains the following:

  • An optimization horizon, \(H\)
  • A cost function for each stage of the horizon, \(\ell_k(\boldsymbol{x}, \boldsymbol{u}) \in \mathcal{R}\), \(0 \leq k \leq H\)
  • Dynamics functions for each stage of the horizon, \(\boldsymbol{f}_k(\boldsymbol{x}, \boldsymbol{u}) \in \mathcal{R}^n\), \(0 \leq k \leq H\)
  • Constraint functions for each stage of the horizon, \(\boldsymbol{c}_k(\boldsymbol{x}, \boldsymbol{u}) \in \mathcal{R}^c\), \(0 \leq k \leq H\)

Of the above, all stage cost and dynamics functions must be defined, but
constraints may be left empty.

Note that models optimize for \(H\) total steps while considering the initial
state to be constant, whereas the initial controls can be altered. This means
that there are \(H\) total controls (\(\boldsymbol{u}_0\) to \(\boldsymbol{u}_{H-1}\)) and \(H + 1\) total states (\(\boldsymbol{x}_0\) to
\(\boldsymbol{x}_H\)), with \(\boldsymbol{x}_0\) being constant. At the terminal stage (stage \(H\)), there are no
controls and, as such, stagewise functions must be appropriately defined to
ignore them. Predefined functions all have constructors to account for this.

Models may be defined either by passing custom function implementations, or
by using XML description files. Some constructors allow for defining a model
using an XML file, but without passing the required cost functions. This is
done to allow access to robot-related algorithms such as forward dynamics,
which may be used to define model costs. Note that, if such constructors are
used, the finalize method must be called before attempting to use the model
for optimization. The user is responsible for either manually assigning all
required costs, or passing them to the finalize method.

Initialize an SSQP Model.

Positional arguments (required):
horizon (int): Optimization horizon (excluding initial stage)
dt (float): Optimization time step

Keyword arguments (optional):
urdf_path (str): Path to URDF file to use for the system dynamics
mjcf_path (str): Path to MJCF file to use for the system dynamics
free_flyer (bool): Whether the model has a floating base
from_preset (ssqpy.model.Preset): Use a preset urdf instead of
supplying a path; mutually exclusive withurdf_path,
mjcf_path and free_flyer
solver_mode (ssqpy.model.SolverMode): The solver mode to solve in
integration (ssqpy.model.Integration): The integration method to use
ignore_innate_constraints (bool): Whether to ignore XML constraints
actuated_joints (list of int): List of joints to apply controls to;
if non-empty, all joints whose indices are not included will not be
actuated

getFullAccelerationVector ¶

getFullAccelerationVector(x, u, forces=[], wrenches=[])

Returns the full acceleration vector
Input:

  • x: The model state
  • u: The model controls
  • forces: The linear forces the force part of u refers to, in order (see getForces); only used in Reduced Inverse mode
  • wrenches: The wrenches the force part of u refers to, after the linear forces (see getWrenches); only used in Reduced Inverse mode

Note: For Inverse dynamics mode, this function is trivial, since it only
returns the non-force part of the control vector
Note: XML-based function

getActuatedTorqueVector ¶

getActuatedTorqueVector(x, u, forces=[], wrenches=[])

Returns the actuated joint torques that realize the given controls
Input:

  • x: The model state
  • u: The model controls
  • forces: The linear forces the force part of u refers to, in order (see getForces)
  • wrenches: The wrenches the force part of u refers to, after the linear forces (see getWrenches)

The torques come from the inverse dynamics, accounting for the given
forces. In Reduced Inverse mode, the full acceleration
vector is reconstructed first (see getFullAccelerationVector)

Note: Only defined in Inverse and Reduced Inverse dynamics modes
Note: XML-based function
